# Writing architecture decisions

Add one Markdown file per decision using the `adr-NNN-short-name.md` convention. Keep the record focused on one choice and include:

- **Status** — proposed, accepted, superseded, or rejected.
- **Context** — the problem and constraints.
- **Decision** — what the project will do.
- **Consequences** — benefits, trade-offs, and follow-up work.

Decisions should describe this project, not generic framework templates. Update the index when adding a new accepted decision.
