# MF1-01–07 Resources and Entitlement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver MF1-01–07 runtime for tenant-scoped workspace/reviewer data, ORG_ADMIN workforce provisioning and credentials, organization Drone inventory/documents, and recorded permit/compliance inputs, with entitlement checks on MF1 operations.

**Architecture:** Keep identity and tenant ownership in `users`, entitlement reads in `subscriptions`, credentials in `workforce`, and Drone/compliance catalog in `assets` as specified by the approved reset ownership split. Expose only narrow feature-owned facades; do not implement registration/subscription activation, external government verification, MF2 readiness, or inspection workflow. This plan is the prerequisite producer for the MF1-08–10 and MF1-11–14 plans.

**Tech Stack:** Java 21, Spring Boot 4.1, Spring Modulith, Spring Data JPA, Flyway V24–V26 target schema, PostgreSQL Testcontainers, JUnit 5, AssertJ, MockMvc, MinIO adapter only for file bytes where existing storage ports support it.

**Spec:** `docs/superpowers/specs/2026-10-08-mf1-organization-resources-inspection-setup-design.md`

## Dependencies

- **Predecessor:** Enterprise SaaS reset on backend `main` (V24–V26, four canonical roles, organization registration) and Report 3/Business Flows v4.0.
- **Successor:** `2026-10-08-mf1-08-10-asset-pair.md` consumes `UserAccess`/workforce checks and same-org ACTIVE Drone inventory; `2026-10-08-mf1-11-14-inspection-dispatch.md` consumes entitlement, workforce, Drone and compliance facades.
- **Supporting Flow excluded:** this plan does not create organizations or activate subscriptions. It only reads current subscription entitlement and denies new MF1 mutations when not entitled.

## Global Constraints

- Current roles are exactly `ADMIN`, `ORG_ADMIN`, `INSPECTOR`, and `MAINTENANCE_ENGINEER`.
- `ORG_ADMIN` is scoped to one customer organization; organization IDs come from the authenticated principal, never the request body.
- Do not implement organization registration, subscription plan activation/renewal, online billing, MF2–MF4, or retired marketplace/WF1 schedule proposals.
- `ADMIN` does not gain customer technical decision rights or implicit unrestricted tenant-data access.
- Do not claim government credential/permit verification. Store issuer, reference, dates, evidence and attributable internal review only.
- Never rewrite V1–V26. Add a forward migration only after tests prove a target schema deficiency.
- Preserve historical WF1 Report 5 IDs/outcomes; add target MF1 test IDs only after execution evidence exists.
- Use `ApiResponse<T>` and RFC 9457 ProblemDetail with stable codes; use tenant-scoped repository queries.
- Do not push, open a PR, merge, deploy, or send external messages without explicit authorization.

## Review Focus

1. ORG_ADMIN attempts to create/suspend an ADMIN, ORG_ADMIN, or user in another organization → reject without changing role/session/tenant.
2. A valid same-tenant user is suspended after credential creation → historical credential remains, but cannot qualify for future pairing/assignment.
3. Expired/suspended entitlement attempts a new MF1 write → deny new work while preserving existing resources/history.
4. A Drone with MAINTENANCE/SUSPENDED/RETIRED status or expired required Drone document is selected → not eligible for MF1-09 pairing; do not claim permit readiness.
5. Cross-tenant Drone/document/permit identifier substitution → non-disclosing 404 and no foreign resource exposure.
