# MF1-08–10 Asset and Pair Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an ORG_ADMIN create an organization-owned asset with exactly one active same-organization Inspector/Drone default pair, atomically and with auditable attribution.

**Architecture:** Extend the existing `assets` create use case, using contracts delivered by Plan 1 for subscription entitlement, active Inspector qualification/status and Drone inventory. Persist `Asset` plus `AssetPairAssignment` in one transaction; rely on V25/V26 composite tenant FKs and active-pair uniqueness unless tests establish a concrete schema gap. No inspection, schedule proposal, due-cycle generation or dispatch is included.

**Tech Stack:** Java 21, Spring Boot 4.1, Spring Modulith, JPA, Flyway V24–V26, PostgreSQL Testcontainers, MockMvc, JUnit 5, AssertJ.

**Spec:** `docs/superpowers/specs/2026-10-08-mf1-organization-resources-inspection-setup-design.md`

## Dependencies

- **Predecessor:** Plan 1 `2026-10-08-mf1-01-07-resources.md` must be complete, or an approved equivalent must provide `SubscriptionEntitlement.requireActive(UUID organizationId, Instant at): void` (throws stable `SUBSCRIPTION_INACTIVE` when denied), `WorkforceService.requireActiveInspector(UUID inspectorId, UUID organizationId): ActiveInspector`, and organization-scoped ACTIVE Drone lookup `DroneRepository.findByIdAndOrganizationId(UUID droneId, UUID organizationId)`.
- **Successor:** Plan 3 `2026-10-08-mf1-11-14-inspection-dispatch.md` consumes the active pair assignment and its version as an immutable inspection snapshot source.
- This plan is MF1-08–10 only. Supporting Flow, MF1-01–07 provisioning, MF1-11–14 inspection creation/dispatch, MF2–MF4, and retired WF1 schedule proposals are excluded.

## Global Constraints

- Current roles are `ADMIN`, `ORG_ADMIN`, `INSPECTOR`, `MAINTENANCE_ENGINEER` only.
- Tenant ID comes from the authenticated ORG_ADMIN, never from request data.
- Foreign-tenant resources return a non-disclosing 404; same-tenant inactive/wrong-role/unavailable resources return a stable ProblemDetail code.
- Asset creation and initial active pair are one transaction: either both persist or neither persists.
- Pair is a mutable asset default, not a reservation, permit, readiness decision, or inspection dispatch.
- Do not add global ADMIN asset visibility or support access in this slice.
- Do not rewrite V1–V26; use a new forward migration only when a tested schema deficiency requires it.
- Preserve historical Report 5 WF1 IDs/outcomes. Add new target MF1 cases under FE-02 / MF1 / `Feature 1` after the implementation is tested.
- No frontend/mobile UI in this slice; no Jira, push, PR, merge, deploy, or external messages.

## Review Focus

1. A pair insert fails after asset flush → both rows roll back; real PostgreSQL assertion.
2. Same-role ORG_ADMIN uses foreign tenant Inspector/Drone IDs → non-disclosing rejection, no writes.
3. Same-tenant inactive Inspector, wrong-role user, or non-ACTIVE Drone → rejection and no orphan asset.
4. Concurrent duplicate asset code or concurrent active-pair insertion → one succeeds, the other maps to 409 rather than 500.
5. Asset response/update never implies pair change, readiness, permit approval, or dispatch.
