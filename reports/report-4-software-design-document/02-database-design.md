## 2. Database Design

**Files and Persistence Storage Description**

SmartDroneInspection persists structured relational and vector data in **PostgreSQL 17** (with the `pgvector` and `pgcrypto` extensions) and binary media/documents in **MinIO S3-compatible object storage**:

- **Flyway Schema Migration Files (`SmartDroneInspection-backend/src/main/resources/db/migration/V1__baseline.sql` – `V28__persist_field_session_flight_report.sql`)**: Versioned forward SQL migration files managed automatically by Flyway on application startup. Across migrations `V1` through `V28`, the schema defines **36 tables** in the `public` schema (35 application domain tables plus `event_publication` for the Spring Modulith transactional event outbox) along with `hnsw` cosine vector indexes on `repair_knowledge_chunks(embedding)`, composite tenant foreign keys, status check constraints, and optimistic locking (`row_version`) columns.
- **MinIO Object Storage Files (`inspection-evidence` bucket)**: Binary files are streamed through `MinioEvidenceObjectStore` using deterministic or UUID-scoped object keys referenced by PostgreSQL columns:
  - `contracts/requests/{requestId}/{uuid}/{fileName}`: Signed offline service agreement scans (`service_requests.contract_object_key`).
  - `licenses/{userId}/{uuid}-{fileName}` and `drones/registrations/{inspectorId}/{docType}/{uuid}-{fileName}`: Inspector pilot license scans (`inspector_profiles.pilot_license_file_key`) and 3-document drone registration files (`drone_registration_applications`).
  - `assets/{assetId}/documents/{uuid}-{fileName}`: Infrastructure asset engineering drawings and reference documents verified with `SHA-256` checksums (`asset_documents.object_key`).
  - `inspections/{inspectionId}/flight-permits/{uuid}-{fileName}` and `inspections/{inspectionId}/evidence/{uuid}-{fileName}`: Mission flight permits (`inspections.flight_permit_file_key`) and field photographs / `video/mp4` captures (`evidence.object_key`).
  - `reports/{reportVersionId}.pdf` and `maintenance-reports/{reportVersionId}.pdf`: Rendered A4 Inspection Reports and Maintenance Completion Reports generated by `OpenHTMLtoPDF`.

**Table Descriptions**

| No | Table | Description |
| :---: | :--- | :--- |
| 01 | `organizations` | Stores customer organizations that own infrastructure assets, request inspection services, and govern maintenance work orders.<br>- Primary keys: `id`<br>- Foreign keys: None |
| 02 | `users` | Stores user accounts across the five system roles (`ADMIN`, `MANAGER`, `CUSTOMER`, `INSPECTOR`, and `MAINTENANCE_ENGINEER`), account status, `ActorZone`, and organization scope.<br>- Primary keys: `id`<br>- Foreign keys: `organization_id` |
| 03 | `inspector_profiles` | Stores Inspector pilot license numbers, license classes, expiration dates, scanned license files, flight hours, and technical specializations.<br>- Primary keys: `user_id`<br>- Foreign keys: `user_id` |
| 04 | `otp_challenges` | Stores consolidated one-time verification codes (`LOGIN`, `REGISTRATION`, and `PASSWORD_RESET`), expiration timestamps, and attempt counters.<br>- Primary keys: `id`<br>- Foreign keys: `user_id` |
| 05 | `inspector_flight_logs` | Records historical flight missions, flight duration, aircraft details, location, and safety notes for Inspectors.<br>- Primary keys: `id`<br>- Foreign keys: `inspector_user_id`, `recorded_by_user_id` |
| 06 | `auth_sessions` | Tracks active web and mobile login sessions, hashed refresh tokens, expiration times, and session revocation records.<br>- Primary keys: `id`<br>- Foreign keys: `user_id` |
| 07 | `prospective_customer_registrations` | Stores customer organization and initial asset registration requests that require platform review due to restricted airspace proximity.<br>- Primary keys: `id`<br>- Foreign keys: `user_id`, `asset_category_id`, `reviewed_by_user_id` |
| 08 | `drone_registration_applications` | Stores Inspector applications to register owned drones with registration, ownership, and technical inspection documents.<br>- Primary keys: `id`<br>- Foreign keys: `inspector_user_id`, `drone_id`, `reviewed_by_user_id` |
| 09 | `drones` | Catalogs approved drones owned by Inspectors or customer organizations, including serial number, model, and serviceability status.<br>- Primary keys: `id`<br>- Foreign keys: `inspector_owner_id`, `organization_id` |
| 10 | `asset_categories` | Defines the global catalog of infrastructure asset categories managed by platform administrators.<br>- Primary keys: `id`<br>- Foreign keys: None |
| 11 | `assets` | Stores customer infrastructure assets, geographic coordinates, technical profiles, and structural inspection checkpoints (`inspection_items`).<br>- Primary keys: `id`<br>- Foreign keys: `organization_id`, `category_id` |
| 12 | `asset_documents` | Stores engineering drawings and reference documents attached to an infrastructure asset with SHA-256 checksums.<br>- Primary keys: `id`<br>- Foreign keys: `asset_id`, `uploaded_by_user_id` |
| 13 | `service_requests` | Stores one-time and recurring customer inspection requests, preferred time windows, recurrence rules, accepted quotation version, and signed agreement file reference.<br>- Primary keys: `id`<br>- Foreign keys: `organization_id`, `asset_id`, `created_by_user_id` |
| 14 | `service_request_messages` | Stores chat messages exchanged between the Customer and the Platform Manager during service request negotiation.<br>- Primary keys: `id`<br>- Foreign keys: `request_id`, `author_user_id` |
| 15 | `service_request_quotes` | Stores versioned VND quotations proposing the inspection scope, schedule window, Inspector, drone, and fee per occurrence.<br>- Primary keys: `id`<br>- Foreign keys: `request_id`, `inspector_id`, `drone_id`, `issued_by_user_id` |
| 16 | `service_request_occurrences` | Stores scheduled inspection occurrences generated from accepted service requests, including dispatch status and assigned Inspector, drone, and inspection.<br>- Primary keys: `id`<br>- Foreign keys: `request_id`, `inspector_id`, `drone_id`, `inspection_id` |
| 17 | `service_invoices` | Stores per-occurrence service price and VAT, commission, and TNCN rate snapshots, plus the Customer report-acceptance time.<br>- Primary keys: `occurrence_id`<br>- Foreign keys: `occurrence_id` → `service_request_occurrences.id` |
| 18 | `service_payments` | Tracks customer payment status, PayOS/VNPay order code and method, transaction reference, and confirmation time for an invoice.<br>- Primary keys: `occurrence_id`<br>- Foreign keys: `occurrence_id` → `service_invoices.occurrence_id` |
| 19 | `inspector_payouts` | Records the Inspector recipient, invoice payout status, external or simulated payout reference, and recorded time.<br>- Primary keys: `occurrence_id`<br>- Foreign keys: `occurrence_id` → `service_invoices.occurrence_id`, `inspector_id` → `users.id` |
| 20 | `inspection_finance_settings` | Stores platform commission, VAT, and personal income tax rates used to calculate net partner payouts.<br>- Primary keys: `id`<br>- Foreign keys: `updated_by_user_id` |
| 21 | `inspections` | Stores scheduled inspection missions (initial inspections and re-inspections), assigned Inspector and drone, flight permit reference, `findings_confirmed_at` timestamp, indexed `work_order_id` linkage, and 6-state mission status.<br>- Primary keys: `id`<br>- Foreign keys: `organization_id`, `asset_id`, `inspector_id`, `drone_id`, `source_inspection_id` |
| 22 | `field_sessions` | Records on-site field flight sessions, pre-flight safety notes, completion outcome notes, abort reasons, persisted `SmartDroneHub` flight report metrics (`telemetry_source`, `flight_duration_seconds`, `distance_flown_meters`, `max_altitude_meters`, `start_battery_percent`, `end_battery_percent`, `flight_final_state`, `flight_report_note`), GPS flight trace (`flight_trace_json`), and synced flight video reference (`flight_video_evidence_id`).<br>- Primary keys: `id`<br>- Foreign keys: `inspection_id`, `flight_video_evidence_id` |
| 23 | `evidence` | Stores metadata and object storage keys for photographs and MP4 videos captured during field sessions, including capture time and GPS coordinates.<br>- Primary keys: `id`<br>- Foreign keys: `inspection_id`, `field_session_id` |
| 24 | `findings` | Stores AI-suggested defect candidates and Inspector-confirmed defect findings, including defect label, severity, confidence score, and bounding box.<br>- Primary keys: `id`<br>- Foreign keys: `inspection_id`, `evidence_id` |
| 25 | `inspection_reports` | Stores versioned 4-state inspection report records (`SUBMITTED`, `RETURNED`, `PUBLISHED`, `SUPERSEDED`), submission and review timestamps, and return feedback.<br>- Primary keys: `id`<br>- Foreign keys: `inspection_id`, `reviewer_user_id` |
| 26 | `reinspection_defect_verifications` | Stores three-way verification records comparing the original defect finding, engineer repair proof, and new re-inspection evidence.<br>- Primary keys: `id`<br>- Foreign keys: `reinspection_id`, `source_finding_id`, `new_evidence_id` |
| 27 | `maintenance_work_orders` | Stores 12-state corrective maintenance work orders created from published inspection defects, tracking scope, priority, assigned roles, and re-inspection links.<br>- Primary keys: `id`<br>- Foreign keys: `organization_id`, `asset_id`, `source_finding_id`, `source_report_version_id`, `reinspection_id`, `reinspection_report_version_id`, `owner_user_id`, `budget_approver_user_id`, `team_lead_user_id`, `report_author_user_id`, `accepting_reviewer_user_id` |
| 28 | `maintenance_team_members` | Stores Maintenance Engineers assigned to a work order along with their team role (`LEAD`, `REPORT_AUTHOR`, or `MEMBER`).<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id`, `engineer_user_id`, `assigned_by_user_id` |
| 29 | `maintenance_tasks` | Stores individual repair tasks, repair methods, planned schedules, acceptance criteria, and task status under a work order.<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id`, `assigned_engineer_user_id` |
| 30 | `maintenance_estimate_versions` | Stores versioned repair cost estimates prepared by Maintenance Engineers and reviewed by the Customer budget approver.<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id`, `prepared_by_user_id`, `approved_by_user_id` |
| 31 | `maintenance_cost_lines` | Stores itemized planned and actual cost entries (labor, material, equipment, external service, and contingency) for a work order.<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id`, `estimate_version_id`, `task_id`, `entered_by_user_id` |
| 32 | `maintenance_change_orders` | Stores scope or budget change requests submitted during repair execution and decided by the Customer.<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id`, `requested_by_user_id`, `decided_by_user_id` |
| 33 | `maintenance_work_logs` | Stores field repair execution logs, labor hours, test measurements, as-left conditions, and Team Lead verification status.<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id`, `task_id`, `engineer_user_id` |
| 34 | `maintenance_reports` | Stores versioned maintenance completion reports prepared by the Report Author for Customer review.<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id` |
| 35 | `maintenance_acceptance_decisions` | Records independent Customer acceptance decisions, technical review comments, and re-inspection or rework outcomes.<br>- Primary keys: `id`<br>- Foreign keys: `work_order_id`, `report_version_id`, `reviewer_user_id` |
| 36 | `repair_knowledge_chunks` | Stores civil and structural engineering standard excerpts (`TCVN`/`EN`/`ISO`) and 1536-dimensional `pgvector` embeddings used by the maintenance advisor.<br>- Primary keys: `id`<br>- Foreign keys: None |
| 37 | `notifications` | Stores deduplicated in-app notifications (`uq_notifications_deduplication_key`), read status, and navigation target paths for users.<br>- Primary keys: `id`<br>- Foreign keys: `organization_id`, `recipient_user_id` |
| 38 | `audit_events` | Stores append-only security and business audit trail events with actor, action, aggregate type, and aggregate ID.<br>- Primary keys: `id`<br>- Foreign keys: `organization_id`, `actor_user_id` |
| 39 | `event_publication` | Stores Spring Modulith transactional domain event publications and listener completion timestamps for reliable asynchronous delivery.<br>- Primary keys: `id`<br>- Foreign keys: None |
